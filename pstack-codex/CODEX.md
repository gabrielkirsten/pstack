# Running pstack in Codex

Use the original skill, playbook, worker brief, reference files, and scripts under `../pstack/`. Keep these host mappings in effect for every nested skill and playbook. Pass the absolute paths to these notes and the original worker brief to any delegate. Apply the user's request, repository rules, tool permissions, and approval requirements throughout.

- **Workers and panels.** For Cursor's Task tool, use Codex collaboration when available and authorized. Read the named agent definition from `../pstack/agents/` and give the worker its brief. Use independent writable directories when workers change files. Codex workers can share a checkout. Preserve the original reviewer roles, rubric, and independence. Report any unavailable independent or cross-vendor review.
- **Models and setup.** Use the inherited model by default. For explicit setup, retain upstream's role names, budget choices, and confirmation step. Choose only models and effort levels the current host supports. Keep model and effort as separate settings. Store confirmed choices in `~/.codex/pstack/models.md` (or the configured Codex home). On each workflow that selects workers, read that file if present. Honor permitted user-selected overrides. Map Cursor's `auto` and `inherit-parent` to host inheritance.
- **Workspace and history.** Use the host's plan, user-input, task-local wait, and scoped chat-history tools. For generated Codex skills use the project's `.agents/skills/` or the user's selected personal skills directory. Check active Codex chats and worktrees before cleanup. The upstream worktree audit reads Cursor history and cannot establish Codex inactivity.
- **Runtime and evidence.** Run bundled helpers from their original directories, including the PR watcher (Bun), decision log (Bash), and statechart (TypeScript runtime, Java and TLC for a live check). Preserve the upstream checks and verdict criteria when using an equivalent local tool. Prefer the project's own verification harness for Cursor-only control skills. Use the actual forge for PR operations and follow the repository's authorization and signing rules.
- **Host services.** Benny targets Cursor automations. The bot UI skill requires a webhook routine and a secure sender-key handoff. Use these integrations only when the requested host capabilities are available. If a prerequisite is missing, name it. Keep secrets in the host’s credential flow and use the user-approved exposure settings.
